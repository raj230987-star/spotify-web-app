PART 4: FREEING PORT 80 & INSTALLING NGINX REVERSE PROXY
--------------------------------------------------------------------------------
1. If a pre-installed proxy container (such as Traefik) is occupying port 80/443,
   check running containers and stop/remove it so Nginx can bind to port 80:
   docker ps
   docker stop <traefik_container_name>
   docker rm <traefik_container_name>

2. Install Nginx on the Ubuntu VPS:
   apt update
   apt install -y nginx

3. Create the Nginx reverse proxy configuration file:
   cat <<'EOF' > /etc/nginx/sites-available/spotify-app
   server {
       listen 80;
       server_name braj23.sbs 189.72.158.155;

       location / {
           proxy_pass http://127.0.0.1:3000;
           proxy_http_version 1.1;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }

       location /api/ {
           proxy_pass http://127.0.0.1:8000/;
           proxy_http_version 1.1;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   EOF

4. Enable the site, disable the default Nginx site, test syntax, and reload:
   ln -sf /etc/nginx/sites-available/spotify-app /etc/nginx/sites-enabled/spotify-app
   rm -f /etc/nginx/sites-enabled/default
   nginx -t
   systemctl reload nginx

5. Verify HTTP access via IP in browser before configuring DNS:
   Open http://189.72.158.155

PART 8: COMPLETE DEBUGGING & TROUBLESHOOTING PLAYBOOK
--------------------------------------------------------------------------------
ISSUE 1: Browser shows 500 Internal Server Error on /api/chat
- Cause: Backend Python exception (e.g., invalid OpenAI API key, missing data).
- Check logs:
  docker logs --tail 60 spotify-rag-backend
- Fix if OpenAI 401 AuthenticationError appears:
  Check ~/spotify-web-app/backend/.env for typos or "PASTE_" prefixes:
  cat ~/spotify-web-app/backend/.env
  Overwrite with clean key and force-recreate backend container:
  echo "OPENAI_API_KEY=sk-YOUR_ACTUAL_KEY" > ~/spotify-web-app/backend/.env
  cd ~/spotify-web-app && docker compose up -d --force-recreate backend

ISSUE 2: Browser shows 502 Bad Gateway
- Cause: Nginx is running, but backend or frontend Docker container is stopped
  or crashed.
- Check container status:
  docker ps -a
- Restart containers and inspect logs:
  cd ~/spotify-web-app && docker compose up -d
  docker logs --tail 50 spotify-rag-backend
  docker logs --tail 50 spotify-rag-frontend

ISSUE 3: Nginx fails to start or reload ("address already in use" on port 80)
- Cause: Another service or container (like Traefik or Apache) is using port 80.
- Check what process is listening on port 80:
  ss -tulpn | grep :80
- Stop conflicting container/service and reload Nginx:
  nginx -t && systemctl restart nginx

ISSUE 4: Domain braj23.sbs does not load or points to wrong page
- Cause: DNS A record not propagated yet, typo in Name/Value, or conflicting A
  record in Hostinger.
- Check live DNS resolution:
  nslookup braj23.sbs
- Verify Hostinger DNS table has ONLY ONE A record for "@" -> 189.72.158.155.

ISSUE 5: Browser Console shows Mixed Content or CORS error after enabling HTTPS
- Cause: Frontend JavaScript hardcoded http://189.72.158.155:8000 instead of
  using relative "/api/..." paths.
- Fix: Always call relative path "/api/chat" in frontend fetch() requests so
  Nginx handles routing seamlessly over both HTTP and HTTPS.
